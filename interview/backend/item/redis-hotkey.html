超大流量下 Redis HotKey 倾斜与 BigKey 线上治理方案

字节跳动 / 美团后端架构高频考点。深度拆解分布式热点发现与平滑打散 SOP。

1. 问题场景：当百万 QPS 集中在单一 Redis 节点

在大促秒杀或突发热点新闻场景下，单个 Key 的请求量可能骤增至十万甚至百万 QPS，远超单台 Redis 节点的吞吐极限，导致单点 CPU 飙升至 100% 并引发缓存雪崩。

2. 防守 SOP：本地多级缓存 + 动态热点打散

解决 HotKey 的核心原则是**“不让流量全部打到单台 Redis 节点上”**：

// 热点 Key 随机后缀打散伪代码逻辑 String baseKey = "sku_info_10086"; int randomSuffix = ThreadLocalRandom.current().nextInt(10); String shardKey = baseKey + "_" + randomSuffix; // 散列到不同的 Redis 分片节点上
